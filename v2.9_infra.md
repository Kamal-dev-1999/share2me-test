# Share2Me v2.9 Infrastructure Flow Diagram

This document contains the complete infrastructure architecture and data flow for Share2Me (version 2.9) on AWS.

```mermaid
architecture-beta
    group aws(cloud)[AWS Cloud]
    group region(region)[ap-south-1 Region] in aws
    group vpc(vpc)[Share2Me VPC] in region
    group subnet(subnet)[Public Subnet] in vpc

    service eip(internet)[Elastic IP: 13.206.180.239] in vpc
    service igw(internet)[Internet Gateway] in vpc
    
    group ec2(server)[EC2 Instance (t3.micro)] in subnet
    group ecs(container)[ECS Task (share2me-task)] in ec2
    
    service caddy(server)[Caddy Proxy\nAuto-HTTPS] in ecs
    service frontend(server)[Next.js\nFrontend] in ecs
    service backend(server)[Node.js\nBackend] in ecs
    service redis(database)[Redis\nCache] in ecs
    
    service ssm(cloud)[SSM Parameter\nStore] in region
    service ecr(cloud)[ECR\nRegistry] in region
    service cw(cloud)[CloudWatch\nLogs] in region
    
    service users(users)[End Users\n(Browsers)]
    service turn(server)[Metered API\n(TURN Server)]

    users:R --> L:eip
    eip:R --> L:igw
    igw:R --> L:caddy
    
    caddy:R --> L:frontend
    caddy:B --> T:backend
    backend:R --> L:redis
    
    backend:B --> T:turn
    backend:L --> R:ssm
    
    ecs:T --> B:ecr
    ecs:L --> R:cw
```

### Detailed Network & Service Flow

```mermaid
graph TD
    %% Define Styles
    classDef aws fill:#FF9900,stroke:#232F3E,stroke-width:2px,color:black,font-weight:bold;
    classDef container fill:#2496ED,stroke:#000000,stroke-width:2px,color:white,font-weight:bold;
    classDef caddy fill:#00ADD8,stroke:#000000,stroke-width:2px,color:white,font-weight:bold;
    classDef nodejs fill:#339933,stroke:#000000,stroke-width:2px,color:white,font-weight:bold;
    classDef external fill:#EAEAEA,stroke:#333333,stroke-width:2px,stroke-dasharray: 5 5;

    %% External Entities
    User((End Users<br/>HTTPS / WSS)):::external
    DNS[Namecheap DNS<br/>share2.me]:::external
    ZeroSSL[ZeroSSL/LetsEncrypt<br/>TLS Certificates]:::external
    Metered[Metered API<br/>TURN Server]:::external

    %% AWS Infrastructure Boundary
    subgraph AWS[AWS Cloud - ap-south-1]
        IGW[Internet Gateway]
        EIP((Elastic IP<br/>13.206.180.239)):::aws
        SSM[SSM Parameter Store<br/>METERED_API_KEY]:::aws
        ECR[Elastic Container Registry<br/>Docker Images]:::aws
        CW[CloudWatch<br/>Centralized Logs]:::aws

        subgraph VPC[VPC - 10.0.0.0/16]
            subgraph Subnet[Public Subnet - 10.0.1.0/24]
                subgraph EC2[EC2 Instance - t3.micro]
                    subgraph ECS[ECS Task - Docker Bridge Network]
                        Caddy[Caddy Sidecar Proxy<br/>Ports: 80, 443]:::caddy
                        Frontend[Next.js Frontend<br/>Port: 3000]:::container
                        Backend[Node.js Backend & Socket.io<br/>Port: 8000]:::nodejs
                        Redis[(Redis Adapter<br/>Port: 6379)]:::container
                    end
                end
            end
        end
    end

    %% Traffic Flow
    User -->|Visits share2.me| DNS
    DNS -->|Resolves to| EIP
    EIP --> IGW
    IGW -->|TCP 80 / 443| Caddy

    %% Caddy Routing Logic
    Caddy -->|Auto-fetches Certs| ZeroSSL
    Caddy -->|Routes /api/* & Socket.io| Backend
    Caddy -->|Routes All Other Traffic| Frontend

    %% Backend Dependencies
    Backend -->|Websocket Pub/Sub| Redis
    Backend -->|Fetches Secret on Boot| SSM
    Backend -->|Fetches ICE/TURN Credentials| Metered

    %% WebRTC Peer-to-Peer
    User -.->|WebRTC DataChannel<br/>Direct File Transfer| User
    User -.->|Fallback Relay if NAT blocks| Metered

    %% Infrastructure Dependencies
    ECS -.->|Pulls Images| ECR
    ECS -.->|Pushes Container Logs| CW
```
