## 1. Vision & USP

Share2Me Tools is not a clone of iLovePDF. It is a **privacy-first, integrated file operations platform** unique because of what happens *after* a tool processes a file.

### The Core UX Loop

```
Upload File(s)
      │
      ▼
      Choose Tool (Merge, Compress, Convert, etc.)
      │
      ▼
      Processing (client-side WASM where possible, server for heavy ops)
      │
      ▼
┌─────────────────────────────────────────────────────────┐
│           WHAT DO YOU WANT TO DO WITH THIS?             │
│                                                         │
│  [⬇ Download]  [🔗 Share via P2P]  [📁 Share via G2P]  │
│  [📤 Send to Google Drive]  [⚙ Apply Another Tool]      │
└─────────────────────────────────────────────────────────┘
```

This "Post-Processing Action Panel" is the single biggest UX differentiator. No other tool does this. Users never need to download → re-upload → share.

### Hard USPs
1. **Zero server retention** — processed files are client-side blobs or R2 objects deleted within 15 minutes
2. **Integrated sharing** — P2P, G2P, and Google Drive are first-class post-processing actions
3. **Google Drive without us touching your data** — we proxy the upload using the user's token; we never store the token or the file content
4. **Persona-aware quotas** — PERSONAL: 50MB, EDUCATOR: 200MB, BUSINESS/PRINT_SHOP: 500MB
5. **Chained operations** — compress → watermark → protect, all in one session

### Key Architectural Decisions

| Decision | Choice | Rationale |
|:---|:---|:---|
| PDF Processing (client) | `pdf-lib` (JS-native) | No binary dependencies; runs in browser and Node identically |
| Heavy Conversion | LibreOffice headless sidecar | Industry standard; handles complex DOCX/XLSX layouts. Free. |
| HTML → PDF | Puppeteer (headless Chrome) | Only tool that handles modern CSS and JS-rendered pages |
| OCR | Tesseract.js WASM (client), server fallback | Zero cost for most users; high accuracy on clean docs |
| AI tools | OpenAI/Gemini API (server-side) | Requires secure API key management |
| Job Queue | BullMQ + Redis | Already in stack; supports retries, timeouts, concurrency control |
| Job Progress | Server-Sent Events (SSE) | Simpler than WebSocket; uses HTTP/2; auto-reconnects |
| Temp Storage | Cloudflare R2, 15-min TTL via lifecycle rule | Hard deletion enforced at infrastructure level |
| Google Drive auth | OAuth 2.0, `drive.file` scope only, httpOnly cookie | Minimal permissions; no token persistence |

## 3. Processing Pipeline Design

### Tier 1 — Client-Side (Browser — Zero Server Cost)

| Tool | Library | Notes |
|:---|:---|:---|
| Merge PDF | `pdf-lib` | Handles encrypted PDFs with known password |
| Split PDF | `pdf-lib` | Page range extraction |
| Rotate PDF | `pdf-lib` | Per-page rotation |
| Reorder Pages | `pdf-lib` | Visual drag-and-drop reorder |
| Crop PDF | `pdf-lib` | Sets MediaBox/CropBox per page |
| Add Page Numbers | `pdf-lib` | Custom position and font |
| JPG/PNG → PDF | `pdf-lib` | One image per page |
| PDF → JPG | `PDF.js` | Canvas render per page → Blob |
| Watermark | `pdf-lib` | Opacity-controlled text/image layer |
| Protect PDF | `pdf-lib` | AES-256 PDF encryption |
| Unlock PDF | `pdf-lib` | Decryption with user password |
| Compress PDF | `pdf-lib` + image re-encoding | Re-encodes embedded images at lower quality |

**Client-Side Job Lifecycle:**
```
1. Files validated (type, size vs persona quota)
2. Files read as ArrayBuffer in browser
3. Web Worker spawned → processing runs off main thread (no UI freeze)
4. Progress emitted via worker.postMessage → progress bar updates
5. Output Blob transferred back to main thread
6. ActionPanel rendered with Blob URL
7. Blob auto-GC'd when user navigates away
```

### Tier 2 — Server-Side (Heavy Operations via BullMQ)

| Tool | Engine | Async | Timeout |
|:---|:---|:---|:---|
| DOCX → PDF | LibreOffice headless | Yes | 120s |
| XLSX → PDF | LibreOffice headless | Yes | 120s |
| PPTX → PDF | LibreOffice headless | Yes | 120s |
| HTML → PDF | Puppeteer | Yes | 60s |
| PDF → DOCX | LibreOffice + post-process | Yes | 180s |
| OCR (large) | Tesseract server-side | Yes | 240s |
| AI Summarize | GPT-4o / Gemini Flash | Yes | 30s |
| Translate PDF | DeepL + pdf-lib | Yes | 60s |

**Server-Side Job Lifecycle:**
```
1. Client POSTs metadata → receives job_id + presigned R2 upload URL
2. Client PUTs file directly to R2 (max 500MB, server never touches bytes)
3. Client subscribes to SSE stream: GET /api/tools/jobs/:job_id/stream
4. BullMQ worker picks job → processes with engine
5. Output written to R2 (tools/output/ prefix, 15-min TTL)
6. SSE emits: { type: 'complete', output_url: '...' }
7. R2 lifecycle rule deletes output object after 15 minutes
```

**Why SSE not WebSocket for progress:**  
SSE is unidirectional (server→client), uses standard HTTP/2 multiplexing, needs no handshake upgrade, and auto-reconnects. For job progress, this is exactly what is needed — no bidirectionality required.

## 4. Google Drive Integration Architecture

### The Core Principle
**We are a conduit, not a vault.** The user's access token exists only in server memory for the duration of one upload/import request. It is never written to any database, log file, or disk.

### OAuth Flow

```
User clicks "Connect Google Drive"
        │
        ▼
GET /api/drive/auth → redirects to Google OAuth
  Scope: https://www.googleapis.com/auth/drive.file
  (App can only access files IT created — user's existing Drive is invisible)
        │
        ▼
User approves → Google redirects to GET /api/drive/callback?code=...
        │
        ▼
Backend exchanges code for access_token
  access_token → stored in encrypted httpOnly SameSite=Strict Secure cookie
                  Expiry: 55 minutes (matches Google token lifetime)
  refresh_token → NOT STORED (intentional privacy decision)
        │
        ▼
Redirect to /tools?drive=connected
```

**Why no refresh token storage:**  
Storing refresh tokens creates a high-value attack target. With `drive.file` scope, re-authorization takes 2 clicks (Google shows "Continue as [email]" — no full re-consent). This is a deliberate privacy design decision.

### Drive Upload Proxy

```
POST /api/drive/upload
Body: { r2_key, filename, mime_type }
(access_token read from httpOnly cookie — never from request body)

Backend:
1. Reads access_token from cookie
2. Creates resumable upload session with Google Drive API
3. Streams bytes: R2.getObject(r2_key) → Google Drive API (resumable upload)
4. File bytes pass through server RAM only momentarily — never written to disk
5. Returns { drive_file_id, drive_view_url }
```

### Drive Import (Receive from Drive)

```
User clicks "Import from Google Drive"
        │
        ▼
GET /api/drive/picker → returns signed picker session token
Frontend renders Google Picker API (Google's own UI — we see only file_id)
        │
        ▼
User selects file → Google Picker returns file_id (browser-side)
        │
        ▼
POST /api/drive/import { file_id }
Backend: Drive API → streams file → writes to R2 (tools/import/ prefix)
Returns: { r2_key, filename, sizeBytes }
Client uses r2_key as tool input
```

## 5. Post-Processing Workflow

After any tool completes (client-side Blob or server-side R2 key), the user sees:

```
┌────────────────────────────────────────────────────────────────┐
│  ✅ compressed-report.pdf  (2.3 MB → 0.8 MB, −65%)            │
│                                                                │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │
│  │ ⬇ Download  │ │ 🔗 P2P Share │ │ 📁 G2P Inbox │           │
│  └──────────────┘ └──────────────┘ └──────────────┘           │
│                                                                │
│  ┌──────────────────────────────┐ ┌─────────────────────┐     │
│  │ 📤 Save to Google Drive      │ │ ⚙ Apply Another Tool │     │
│  └──────────────────────────────┘ └─────────────────────┘     │
│                                                                │
│  Expires in: 14:23  ·  Output auto-clears for your privacy     │
└────────────────────────────────────────────────────────────────┘
```

### Action Implementations

**Download:**  
- Client Blob → `URL.createObjectURL(blob)` + programmatic `<a download>` click  
- Server output → Presigned R2 GET URL (`Content-Disposition: attachment`)

**P2P Share:**  
- Blob is transiently saved to R2 with 10-min TTL  
- User navigated to `/p2p?tool_output_key=...`  
- SendFlow detects the query param and pre-loads the file  
- Works even after hard refresh of the P2P page

**G2P Inbox:**  
- Output uploaded as a self-submission to the vendor's own inbox  
- Managed from G2P dashboard: download, access control, TTL

**Save to Google Drive:**  
- Triggers Drive OAuth if not connected (returns to same page after)  
- File streamed from R2 → Drive (as described in §4)  
- Returns Drive file link for user to copy

**Apply Another Tool:**  
- Output becomes new input — the tool picker opens  
- Compatible tools highlighted  
- Chain history sidebar shows: Compress → Watermark → Protect  
- All intermediate R2 keys preserved until chain ends, then eligible for cleanup

## 6. Tool Registry & Execution Model

### Extended Registry Interface

```typescript
// frontend/src/lib/pdfTools.ts — extended

interface PdfTool {
  slug: string;
  title: string;
  description: string;
  icon: LucideIcon;
  category: ToolCategory;
  phase: 'ready' | 'soon';
  processingTier: 'client' | 'server' | 'hybrid';
  // 'hybrid' = try client first, fall back server if >50MB or WASM fails
  maxFileSizeBytes: {
    PERSONAL:   number;  // 50MB
    EDUCATOR:   number;  // 200MB
    BUSINESS:   number;  // 500MB
    PRINT_SHOP: number;  // 500MB
  };
  maxInputFiles: number;      // 1 for most; Infinity for merge
  outputMimeType: string;
  accept: string[];
  tag?: string;
}
```

### Backend Tool Router

```
POST /api/tools/:slug/process

Middleware chain:
  1. resolveSession (anonymous OK)
  2. resolvePersona (reads from DB if logged in, else 'PERSONAL')
  3. requireToolQuota (checks file size vs persona limit)
  4. validateToolSlug (must exist in server-side TOOL_REGISTRY)

Handler:
  → If processingTier === 'client': 400 (should not call server)
  → Create BullMQ job → return { job_id, sse_url }
```

### Quota Enforcement

```javascript
// middleware/requireToolQuota.js
function requireToolQuota(req, res, next) {
  const tool = SERVER_TOOL_REGISTRY[req.params.slug];
  const persona = req.session.persona ?? 'PERSONAL';
  const maxBytes = tool.maxFileSizeBytes[persona];

  if (parseInt(req.body.sizeBytes) > maxBytes) {
    return res.status(429).json({
      error: 'quota_exceeded',
      limit_mb: maxBytes / 1024 / 1024,
      upgrade_to: getMinPersonaForFileSize(parseInt(req.body.sizeBytes)),
    });
  }
  next();
}
```

## 7. Security Model

| Threat | Mitigation |
|:---|:---|
| Malicious PDF (PDF bombs) | `pdf-lib` is pure JS — no shell execution. LibreOffice runs in isolated Docker with no network access and resource limits (2GB RAM cap, CPU throttle). |
| File content logging | Zero log levels read file bytes. BullMQ records only slug + size + status. Blobs and R2 streams are never logged. |
| Cross-user output access | R2 output keys: `tools/{session-uuid}/{job-uuid}/output`. Only job creator (via session cookie) receives the URL. Session UUID is generated server-side. |
| SSRF via HTML→PDF | Puppeteer sandboxed in isolated container. `--no-sandbox` NOT used. Allowlist: HTTPS only. Internal IP ranges blocked via iptables rules in the container. |
| Drive token leakage | Access token: httpOnly, SameSite=Strict, Secure cookie only. Never in localStorage, never in logs, never in DB. |
| File size abuse | Enforced at 3 layers: (1) frontend validation, (2) presigned URL `Content-Length` max, (3) BullMQ job validator. |
| Anonymous quota abuse | Rate limit: 5 uploads/60s per IP, 10 jobs/10min per IP, max 3 concurrent anonymous jobs per IP (BullMQ concurrency). |
| R2 temp object persistence | R2 lifecycle rule on `tools/` prefix: hard-delete at 15 minutes regardless of application state. |

### Content Security Policy Additions

```
Content-Security-Policy:
  default-src 'self';
  worker-src blob: 'self';
  connect-src 'self' *.googleapis.com *.r2.cloudflarestorage.com;
  script-src 'self' 'wasm-unsafe-eval';
```

## 8. Database Schema Delta

```sql
-- Tool job tracking (server-side jobs only)
CREATE TABLE tool_jobs (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  vendor_id     UUID REFERENCES vendors(id),      -- NULL for anonymous users
  session_id    TEXT NOT NULL,                     -- SHA-256 hash of session cookie
  tool_slug     VARCHAR(50) NOT NULL,
  status        VARCHAR(20) NOT NULL DEFAULT 'queued'
                CHECK (status IN ('queued', 'processing', 'complete', 'failed', 'expired')),
  input_r2_key  TEXT NOT NULL,
  output_r2_key TEXT,
  input_bytes   BIGINT NOT NULL,
  output_bytes  BIGINT,
  error_message TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  completed_at  TIMESTAMPTZ,
  expires_at    TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '15 minutes'
);

CREATE INDEX idx_tool_jobs_session ON tool_jobs(session_id, created_at DESC);
CREATE INDEX idx_tool_jobs_expire  ON tool_jobs(expires_at) WHERE status != 'expired';

-- Immutable tool usage analytics (no file content)
CREATE TABLE tool_usage_events (
  id          BIGSERIAL PRIMARY KEY,
  tool_slug   VARCHAR(50) NOT NULL,
  persona     VARCHAR(20),
  input_bytes BIGINT NOT NULL,
  success     BOOLEAN NOT NULL,
  duration_ms INTEGER,
  occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_tool_usage_slug ON tool_usage_events(tool_slug, occurred_at DESC);
```

### Processing Hook

```typescript
// hooks/useToolProcessor.ts
function useToolProcessor(slug: string) {
  const [status, setStatus] = useState<'idle'|'processing'|'complete'|'error'>('idle');
  const [progress, setProgress] = useState(0);
  const [output, setOutput] = useState<ProcessedOutput | null>(null);

  async function process(files: File[], config: ToolConfig) {
    const tool = TOOL_REGISTRY[slug];
    setStatus('processing');

    if (tool.processingTier === 'client') {
      const worker = new Worker('/workers/pdf-processor.js', { type: 'module' });
      worker.postMessage({ slug, buffers: await toArrayBuffers(files), config });
      worker.onmessage = (e) => {
        if (e.data.type === 'progress') setProgress(e.data.pct);
        if (e.data.type === 'complete') {
          setOutput({ source: 'blob', blob: e.data.blob, filename: e.data.filename });
          setStatus('complete');
        }
        if (e.data.type === 'error') {
          setStatus('error');
        }
      };
    } else {
      const { r2_key, upload_url } = await getUploadUrl(files[0]);
      await uploadToR2(upload_url, files[0]);
      const { job_id, sse_url } = await startJob(slug, r2_key, config);
      await streamProgress(sse_url, { onProgress: setProgress, onComplete: (data) => {
        setOutput({ source: 'r2', download_url: data.output_url });
        setStatus('complete');
      }});
    }
  }

  return { process, status, progress, output };
}
```

## 11. Edge Cases & Failure Handling

### 11.1 SharedArrayBuffer Not Available (WASM restriction)
**Scenario:** Browser security policy blocks SharedArrayBuffer (needed by some WASM builds).  
**Handling:** Tool checks `typeof SharedArrayBuffer !== 'undefined'`. If unavailable, auto-escalates to server-side processing. UI shows "Processing securely on server..." instead of client progress bar.

### 11.2 LibreOffice Crashes Mid-Job
**Scenario:** Malformed DOCX causes LibreOffice to hang or crash.  
**Handling:** LibreOffice is spawned with `child_process.spawn` + 120s kill timeout. Non-zero exit → BullMQ marks job `failed` → SSE emits error. Input R2 object retained for 1hr for debugging, then cleaned by lifecycle rule.

### 11.3 Google Access Token Expires Mid-Drive-Upload
**Scenario:** Access token (55min) expires during a large resumable upload.  
**Handling:** Google resumable uploads support session recovery with a new token. Our backend catches the 401, emits `{ error: 'drive_token_expired' }`, and prompts user to reconnect Drive. File stays in R2. User reconnects and re-triggers upload — the R2 object is still there within the 15-min window.

### 11.4 User Closes Tab After Clicking "P2P Share"
**Scenario:** File Blob is in memory, user navigates to `/p2p`, closes tab. Blob is gone.  
**Handling:** Before navigating, Blob is written to R2 temp key (`tools/p2p-bridge/{uuid}`) with 10-min TTL. `/p2p?tool_output_key=...` causes SendFlow to `fetch` the temp key and pre-load. Even hard refresh of P2P page works within the 10-min window.

### 11.5 Job Status `expired` But R2 Object Still Exists
**Scenario:** DB marks job expired; R2 lifecycle rule hasn't fired yet. User tries download.  
**Handling:** API checks `job.status === 'expired' OR job.expires_at < NOW()` before generating presigned URL. Returns `410 Gone` immediately — no URL generated regardless of R2 state.

### 11.6 Chained Tools — Input R2 Key Expires Before Chain Completes
**Scenario:** User starts a chain. Between tool 2 and tool 3, the original tool 1 output R2 object expires (15 min).  
**Handling:** For chained jobs, each intermediate output R2 key gets its TTL extended by 15 minutes from the time it becomes a chain input. The extension is done via an R2 object metadata update (or copy-with-new-TTL). This is done atomically in the BullMQ job that consumes that input.

### 11.7 Anonymous User Rate Limit Hit During Batch
**Scenario:** Anonymous user submits 15 compression jobs rapidly.  
**Handling:** After job 10 in 10 minutes, `429 Too Many Requests` returned with `Retry-After: {seconds}`. UI shows "You've hit the free limit — sign in for higher limits". If signed in, their persona quota is used instead of IP-based quota.

## 13. Technology Decisions & Rationale

| Decision | Chosen | Why Not Alternatives |
|:---|:---|:---|
| PDF client ops | `pdf-lib` | `PDF.js` is read-only. `jsPDF` creates but can't modify. `pdf-lib` handles both creation and modification of existing PDFs. |
| Compression | `pdf-lib` + image re-encode | `Ghostscript` is better but needs server. Client-side handles 70% of use cases at zero cost. |
| Server conversion | LibreOffice headless | `pandoc` handles markup but poor for complex Office layouts. `Adobe PDF Services` costs $0.05/page. LibreOffice is free, used by Nextcloud/Collabora. |
| Job queue | BullMQ | `Agenda` (MongoDB) adds DB. `Bee-Queue` lacks retries. BullMQ: Redis-backed (already in stack), priorities, rate limits, Bull Board UI. |
| Job progress | SSE | WebSocket: bidirectional overkill. Long-polling: latency + overhead. SSE: simple, HTTP/2 native, auto-reconnects. |
| OCR | Tesseract.js WASM | Google Vision: $1.50/1000 pages. Azure AI: similar pricing. Tesseract: free, client-side for clean docs. |
| Drive scope | `drive.file` only | `drive.readonly` or `drive` over-permissioned. `drive.file` = app only sees its own files. User's Drive contents are invisible to us by design. |
| Anonymous tool auth | Session cookie | Forcing accounts kills conversion rate. Session cookie gives rate limiting + quota without friction. |
| HTML→PDF | Puppeteer sidecar | `wkhtmltopdf` doesn't handle modern CSS/JS. `WeasyPrint` struggles with complex layouts. Puppeteer renders what Chrome renders. |
